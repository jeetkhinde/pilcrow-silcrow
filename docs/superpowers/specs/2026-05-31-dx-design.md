## D2 — `req.fsr.invalidate_dep_key`

### Problem

Actions call `req.fsr.invalidate_route(path)` N times — one per consumer route. Forgetting a route produces silent stale UI. The dep-key graph already exists: `#[pilcrow::depends_on_route(table, param)]` registers a dep key at slot registration time, and `FsrStore::invalidate_dep_key` fans out to all matching rows. It is not exposed on `FsrHandle`.

### Change

Add one method to `FsrHandle` (`crates/runtime/src/fsr/handle.rs`), following the exact same pattern as `invalidate_route`:

```rust
pub async fn invalidate_dep_key(&self, table: &str, param: &str) {
    let Some(ref store) = self.store else { return };
    let key = format!("{table}:{param}");
    if let Err(e) = store.invalidate_dep_key(&key).await {
        tracing::warn!(key, error = %e, "fsr.invalidate_dep_key: DB error");
    }
}
```

Marking rows stale is sufficient — the background watcher task picks them up and re-bakes, exactly as with `invalidate_route`. No separate broadcast call is needed.

### Address-book update

`address-book/pages/(app)/contacts/[contact_id]/index.rs` — `favorite` and `destroy` actions:

```rust
// before (3 calls)
req.fsr.invalidate_route(&format!("/contacts/{id}")).await;
req.fsr.invalidate_route(&format!("/contacts/{id}/edit")).await;
req.fsr.invalidate_route("/").await;

// after (1 call)
req.fsr.invalidate_dep_key("contacts", &id).await;
```

Works because all three routes already register `#[pilcrow::depends_on_route(contacts, contact_id)]`, generating dep key `contacts:{id}`.

### Error handling

- No matching rows → `store.invalidate_dep_key` marks zero rows; watcher finds nothing new; no-op.
- DB error → logged via `tracing::warn!`, silently swallowed (same pattern as `invalidate_route`).

### Tests

- Unit: `FsrHandle::invalidate_dep_key` with mock store; assert broadcast called with correct paths.
- Integration: address-book `favorite` action → assert all 3 dependent routes receive stale broadcast.
- Existing dep-key registration tests in `routekit/src/fsr.rs` cover the registration side.

## D1 — `s-optimistic` HTML Attribute

### Problem

The optimistic engine (`publishOptimistic` / `revertOptimistic` / `confirmOptimistic`, silcrow.js:2540–2596) is only reachable via `Silcrow.submit(form, { optimistic: {...} })` in JS. `s-live` elements are updated by the SSE "live" event handler (silcrow.js:1293–1306) which directly sets `textContent` via `data-pilcrow-live-field` — a separate system from atoms. The address-book works around both gaps with `window.__optimisticStar`.

### Attribute syntax

```html
<form s-post="?/action" s-optimistic="scope_name">
  <input type="hidden" name="field" value="optimistic_value" />
  ...
</form>
```

`scope_name` = atom scope (and live-field name). Serialized non-file FormData becomes the optimistic patch data.

### Changes to silcrow.js (5 locations)

**① `onSubmit`** — read attribute, serialize, publish:
```js
const optScope = form.getAttribute("s-optimistic");
if (optScope && verb.method !== "GET") {
  const data = {};
  for (const [k, v] of formData) {
    if (!(v instanceof File)) data[k] = v;
  }
  const mutationId = "m-" + Date.now() + "-" + Math.random().toString(36).slice(2);
  publishOptimistic(optScope, data, mutationId);
  navigateOpts.mutationId = mutationId;
}
```

**② `navigate`** — accept `mutationId`, add header, revert on error:
```js
// options destructuring: add mutationId = null
// in buildFetchOptions call: if mutationId, add silcrow-mutation-id header
// in catch block: if (mutationId) revertOptimistic(mutationId);
```

**③ `publishOptimistic` extended** — also patch `s-live` DOM elements, store old `textContent` in snapshot:
```js
// after atom.patch(data):
const liveSnapshots = {};
for (const [k, v] of Object.entries(data)) {
  document.querySelectorAll(`[data-pilcrow-live-field="${CSS.escape(k)}"]`).forEach(n => {
    liveSnapshots[k] = n.textContent;
    n.textContent = v == null ? "" : String(v);
  });
}
// store liveSnapshots in pendingMutations entry alongside existing snapshot
```

**④ `revertOptimistic` extended** — restore live DOM from snapshots:
```js
// after atom.set(entry.snapshot):
for (const [k, old] of Object.entries(entry.liveSnapshots || {})) {
  document.querySelectorAll(`[data-pilcrow-live-field="${CSS.escape(k)}"]`).forEach(n => {
    n.textContent = old;
  });
}
```

**⑤ "live" SSE handler guard** — skip field if pending mutation exists for scope:
```js
// in es.addEventListener("live", ...), inside forEach:
if (pendingByScope.has(k)) return; // stale-patch guard
if (k in data) { n.textContent = ...; }
```

(`pendingByScope` is keyed by scope name = live field name, so the guard is a direct `.has(k)` check.)

### Address-book rewrite

`address-book/pages/(app)/contacts/[contact_id]/index.html`:

```html
<!-- before -->
<form method="post" action="?/favorite" s-post="?/favorite"
      onsubmit="window.__optimisticStar && window.__optimisticStar(this)">
  <button name="favorite" value="{% if favorite %}false{% else %}true{% endif %}">
    <span id="favorite-slot" s-live="favorite_mark">{{ live.favorite_mark.value }}</span>
  </button>
</form>
<script>
  window.__optimisticStar = function (form) { ... };
</script>

<!-- after -->
<form method="post" action="?/favorite" s-post="?/favorite" s-optimistic="favorite_mark">
  <input type="hidden" name="value"
         value="{% if favorite %}☆{% else %}★{% endif %}" />
  <button name="favorite" value="{% if favorite %}false{% else %}true{% endif %}">
    <span s-live="favorite_mark">{{ live.favorite_mark.value }}</span>
  </button>
</form>
<!-- <script> block removed -->
```

The hidden `name="value"` carries the display character to show optimistically — what `window.__optimisticStar` was computing manually. `s-live="favorite_mark"` stays unchanged; the SSE update will be guarded during the in-flight mutation.

### Error handling

| Scenario | Behavior |
|---|---|
| `s-optimistic` on GET form | Skip — guard is `verb.method !== "GET"` |
| File inputs in form | Excluded from serialized data (`instanceof File` check) |
| Network error / server error | `revertOptimistic` in navigate's catch restores atom + live DOM |
| Scope atom didn't exist yet | `resolveAtomByScope(scope, true)` creates it; snapshot = undefined; harmless |
| `revertOptimistic` with no entry | Silent no-op (existing behavior, line 2578) |

### Tests

- Silcrow unit: `onSubmit` with `s-optimistic` form → verify `publishOptimistic` called with correct scope/data, `silcrow-mutation-id` header sent.
- Silcrow unit: network error → verify live DOM restored to original text.
- Address-book E2E: click star → star character changes immediately (before SSE); server confirms → star stays.

## D3 — `s-live:text` / `s-live:class` / `s-live:attr` Modifier Attributes

### Problem

`s-live="field"` patches `textContent` only. A live field controlling both text and a CSS class (e.g. star icon color) requires two mechanisms — one live-updated, one baked at SSR — so the class goes stale. The roadmap calls this the "class trap".

### Syntax

```html
<span
  data-pilcrow-live-field="star"
  s-live:text="star.text"
  s-live:class="star.class"
  class="{{ live.star.class }}"
>{{ live.star.text }}</span>
```

`s-live:<prop>="field.path"` where:
- `<prop>` = any target handled by the existing `setValue` engine: `text`, `class`, `style`, `show`, or any DOM attribute name.
- `field.path` = dot-path into the SSE payload resolved via existing `resolvePath`.

### Change to silcrow.js

CSS attribute selectors cannot prefix-match attribute names, so `querySelectorAll("[s-live:*]")` is not valid. **Solution:** pilcrow codegen (or the template author) adds `data-s-live-mod` to any element that carries `s-live:*` attributes, making them efficiently queryable.

In the "live" SSE handler, after the existing `data-pilcrow-live-field` loop:

```js
document.querySelectorAll("[data-s-live-mod]").forEach(function(n) {
  if (pendingByScope.has(n.getAttribute("data-pilcrow-live-field") || "")) return;
  for (const attr of n.attributes) {
    if (!attr.name.startsWith("s-live:")) continue;
    const prop = attr.name.slice(7); // strip "s-live:"
    const val = resolvePath(data, attr.value);
    if (val !== undefined) setValue(n, prop, val);
  }
});
```

Pilcrow codegen emits `data-s-live-mod` alongside `s-live:*` attributes automatically. Template authors who write `s-live:*` manually must also add `data-s-live-mod`.

`setValue` is the existing binding engine (silcrow.js:633) — handles `text`, `class` (object toggle or string replace), `style`, `show`, `disabled`, arbitrary attributes, URL safety checks.

### Stale-patch guard for modifier elements

Modifier elements that also carry `data-pilcrow-live-field` are protected by the D1 guard (`.has(fieldName)`). Elements without `data-pilcrow-live-field` can add `s-bind="scope"` to opt into the scope-based guard; this is the same `s-bind` attribute `hasPendingMutationForTarget` already reads.

### Server-side

`LiveProp<T>` where `T` is a serializable struct:

```rust
#[derive(Serialize)]
pub struct StarMark {
    pub text: String,
    pub class: String,
}
```

SSE payload: `{ "star": { "text": "★", "class": "text-amber-500" } }`. `s-live:text="star.text"` resolves `.text`; `s-live:class="star.class"` resolves `.class`.

### Address-book D3 update

Extend the D1 rewrite to use an object-valued `FavoriteMark` live field:

*Rust* (`contacts/[contact_id]/index.rs`):
```rust
#[derive(Serialize)]
pub struct FavoriteMark { pub text: String, pub class: String }
```

*HTML* — span becomes:
```html
<span
  data-pilcrow-live-field="favorite_mark"
  s-live:text="favorite_mark.text"
  s-live:class="favorite_mark.class"
  class="{{ live.favorite_mark.class }}"
>{{ live.favorite_mark.text }}</span>
```

*Form hidden inputs* (D1 extended):
```html
<input type="hidden" name="text"  value="{% if favorite %}☆{% else %}★{% endif %}" />
<input type="hidden" name="class" value="{% if favorite %}text-slate-400{% else %}text-amber-500{% endif %}" />
```

D1 optimistic update then patches both `text` and `class` simultaneously via `publishOptimistic`.

### Error handling

| Scenario | Behavior |
|---|---|
| `s-live:*` path unresolvable in payload | `resolvePath` returns `undefined`; `if (val !== undefined)` guard skips silently |
| `s-live:class` value is object `{ cls: true }` | `setValue` → `classList.toggle` per entry (existing behavior) |
| `s-live:href` with unsafe URL | `setValue` → URL safety check rejects it (existing behavior) |

### Tests

- Silcrow unit: "live" SSE event with `s-live:class` element → verify `classList` updated correctly.
- Silcrow unit: `s-live:class` with object value `{ "text-amber-500": true, "text-slate-400": false }` → verify toggle behavior.
- Silcrow unit: unresolvable path → verify no error thrown, element unchanged.
- Address-book: star color class updates on SSE alongside text.
