# DX D2 + D1 + D3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship three DX improvements (D2: `invalidate_dep_key` on FsrHandle; D1: `s-optimistic` HTML attribute; D3: `s-live:*` modifier attributes) across three independent PRs in order D2 → D1 → D3.

**Architecture:**
- D2 is pure Rust: expose the already-existing `FsrStore::invalidate_dep_key` on `FsrHandle`, reducing N route-invalidation calls to one dep-key call.
- D1 is pure JS + HTML: wire the existing `publishOptimistic` / `revertOptimistic` engine to a declarative `s-optimistic` form attribute, also extending it to patch `data-pilcrow-live-field` DOM elements directly and guard them in the SSE "live" handler.
- D3 is JS + Rust + HTML: add `s-live:<prop>="field.path"` modifier attribute support to the SSE "live" handler via a `[data-s-live-mod]` sentinel, and migrate the address-book `favorite_mark` live field from `LiveProp<String>` to `LiveProp<FavoriteMark>` (struct with `text` + `class`).

**Tech Stack:** Rust (sqlx, axum, tracing), vanilla JS (no bundler — single-file `silcrow/src/silcrow.js`), Tera HTML templates, `node build.js` to produce dist + pilcrow asset.

**Worktree rule:** NEVER commit on `main`. Create a fresh worktree for each PR:

      return;
    }
    const snapshot = atom.get();

## PR 3 — D3: `s-live:*` Modifier Attributes

**Context:** Builds on D1 (assumes `window.__optimisticStar` already removed). D1 must be merged before D3 is merged, but D3 can be developed in parallel against D1's branch.
