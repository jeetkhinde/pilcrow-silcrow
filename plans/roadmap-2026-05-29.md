## A. Reliability — features that lie (highest trust impact)

The framework currently advertises behaviour it does not deliver. A spec that lies is worse than a missing feature. Fix the implementation **or** make the surface a hard build error until it works.

- [x] **A1. `#[debounce(N)]` is a runtime no-op.** Implemented — `last_patched_at` column added (migration 0003); `fetch_stale_slots` filters in SQL; `mark_fresh` sets timestamp; global fallback via `[fsr] patch_debounce_secs` (default 0).
- [x] **A2. Redis/SQLite cache providers advertised but not implemented.** Startup panic with clear message for `Sqlite`/`Redis` providers. MCP validation added.

## C. Reliability — security / DoS findings (from security-performance-findings)

- [ ] **C1. Service worker caches private/authenticated GET responses** — `crates/runtime/src/sw.rs` caches any same-origin 200 without honoring `Cache-Control`/`Vary`/cookies. Default to precache assets or an opt-in header. (High)
- [x] **C2. Unbounded response-body buffering** — ✅ Done by Codex: dev reload, service-worker registration, and React island SSR HTML rewriting now share a 10 MiB response-body guard, precheck `Content-Length`, and skip injection/SSR above the cap. (High)
- [ ] **C3. React island SSR blocks async workers** — `island_ssr.rs` takes `std::sync::Mutex` + blocking stdin/stdout to the Node worker. Move to `spawn_blocking`/`tokio::process` + timeout + small worker pool. (High; overlaps B5)
- [ ] **C4. Malformed/oversized form bodies silently become empty forms** — `context.rs` `from_request(...).unwrap_or_default()`. Return 400/413. (Medium)
- [ ] **C5. `LiveProp::poll(Duration::ZERO, ...)` panics** — `tokio::time::interval_at` panics on zero. Clamp to a minimum or error. (Medium)
- [ ] **C6. MCP inspect path traversal** — `inspect_template`/`inspect_code_behind` read absolute paths. Canonicalize + require paths under the app root (`tools/pilcrow-mcp/src/inspect.rs`). (Medium)
- [ ] **C7. No default request body limit** — apply Axum `DefaultBodyLimit` at router construction, configurable. (Medium)
- [ ] **C8. SW activation deletes unrelated caches** — filter deletion to `pilcrow-`-prefixed cache names (`sw.rs`). (Low)
- [x] **C9. ISR inspect endpoint always mounted.** ✅ Resolved by E1/S4 — `isr.rs` and its `/__pilcrow/isr` route were deleted entirely.

## R. Reliability — FSR background tasks & fan-out

- [ ] **R1. FSR background task supervision** — watcher tasks are fire-and-forget; panics silently kill them. Add supervision/logging/restart (`start.rs`, `fsr/watcher.rs`).
- [ ] **R2. FSR fan-out → `buffer_unordered(8)`** — replace stop-and-go `chunks(8)` + `join_all` with `stream::iter(...).buffer_unordered(8)` to keep the pipeline full (carry the row with the result for the later `zip`).
- [ ] **R3. Batch same-file slot patches** — multiple slots targeting one HTML/JSON file currently do independent read/patch/write passes; batch into one (`fsr/watcher.rs`).

## D. DX — surface existing engines declaratively

The engines exist; the ergonomic surface does not, so tutorials teach hand-rolled hacks.

- [ ] **D1. Declarative optimistic binding (`s-optimistic`).** Silcrow already has a full optimistic engine — `publishOptimistic`/`confirmOptimistic`/`revertOptimistic`, `silcrow-mutation-id` header, atom-scope snapshots, auto-revert on `!response.ok`, stale-patch guard (`silcrow/src/silcrow.js:423-474, 2538-2596`). But it is only reachable via `Silcrow.submit(form, { optimistic: {...} })` in JS — there is no HTML attribute. Add `s-optimistic` mapping a form value → atom scope, then rewrite the Address Book favourite step to drop `window.__optimisticStar` in favour of the real engine.
- [ ] **D2. Auto / dep-key FSR invalidation.** Actions hand-list every consumer route (`invalidate_route` ×3). Use the existing `#[depends_on_route(table, param)]` dep-key graph so an action touches one dep key and the framework fans out to all dependent slots — removes the "forget a route → silent stale UI" footgun.
- [ ] **D3. `s-live:class` / attribute patching.** Retire the documented scalar-vs-object "class trap" (scalar `s-live` patches `textContent` only; class baked at SSR goes stale). Let a single live field drive text + class declaratively.
