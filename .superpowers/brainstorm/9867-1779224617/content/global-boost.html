Global Boost — Opt-Out Model

Every anchor is boosted by default. no-boost opts out. No containers needed.

BEFORE — opt-in
<!-- need a container wrapper -->
<div s-boost>
  <a href="/dashboard">Dashboard</a>
  <a href="/settings">Settings</a>
</div>

<!-- outside container = not boosted -->
<a href="/logout">Logout</a>

<!-- partial swap via container -->
<div s-boost s-target="#detail">
  <a href="/t/1">Ticket 1</a>
</div>
AFTER — opt-out
<!-- no wrapper needed, all boosted -->
<a href="/dashboard">Dashboard</a>
<a href="/settings">Settings</a>

<!-- explicit opt-out -->
<a href="/logout" no-boost>Logout</a>

<!-- partial swap: s-target on anchor or container -->
<div s-target="#detail">
  <a href="/t/1">Ticket 1</a>
</div>
Target resolution (unchanged logic, new lookup order)
1. anchor.getAttribute("s-target") // anchor-level wins
2. anchor.closest("[s-target]") // inherit from nearest ancestor
3. document.body // fallback — full page swap
Auto-skip rules (safety — unchanged)
no-boost attributeskip — developer opt-out
External originskip — cross-origin
download attributeskip — file download
target="_blank"skip — new tab
href starts with #skip — hash only
mailto:, tel:, other non-httpskip — non-navigable
What happens to s-boost attribute?
A

Remove s-boost entirely

It was only an opt-in enabler. Now that boost is global, the attribute has no meaning. Containers that want to scope s-target just use s-target directly. Clean break.

B

Keep s-boost as a scope/target container (no-op enabler)

Old markup keeps working. s-boost is now just a scoping marker — links inside it still get boosted (they would anyway), and s-target on it still applies. Migration path for existing code.
