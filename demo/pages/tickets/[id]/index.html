Object LiveProp pattern (both fields):
Both status and priority use the object path — the LiveProp<T> type parameter is a struct that serialises to a JSON object. FSR calls Silcrow.publish("fsr.<slot>", obj); s-use="fsr.<slot>" spreads each key onto the element: text → textContent, class → className.

Why not a scalar for status? A scalar LiveProp<String> uses s-live which patches only textContent. The badge colour comes from the CSS class, not the text — so after an SSE update the badge text would change but the colour would stay stale. Whenever a live field controls both a value and a class, use the object path.
