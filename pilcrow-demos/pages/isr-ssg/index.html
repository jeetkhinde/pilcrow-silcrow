First load shows startup prerender values. After 30s, next request gets stale HTML while a fresh render fires in the background. Click "Bust Cache" to force an immediate re-render.

Key difference from pure SSG: the cache is stored with the ISR TTL (30s), not u64::MAX. After 30 seconds the stale-while-revalidate cycle takes over — load() runs in the background and the cache refreshes automatically.
Key difference from pure ISR: there is no cold-start miss. The cache is warm before the first request arrives because PRERENDER = true triggered __pilcrow_prerender_all() at server startup.
